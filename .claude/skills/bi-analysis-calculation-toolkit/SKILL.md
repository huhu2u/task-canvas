# 数据分析工具箱

## 概述

本 Skill 是一个**索引路由层**，整合了 20 项原子数据分析计算能力。当用户提出数据分析需求时，本 Skill 负责：

0. **数据安全确认**：优先向用户确认数据安全，确保用户知晓，收到明确的确认回复后才能继续执行
1. **理解需求**：解析用户的分析意图和数据特征
2. **路由匹配**：从下方能力索引表中选择最合适的**1个原子能力项**
3. **加载执行**：读取对应原子能力项的完整 reference 说明，严格按照其定义的工作流程执行分析
4. **组合编排**：复杂分析场景下可按序调用多个原子能力项，形成分析链路

> **核心原则**：本 Skill 仅做索引路由，不改变任何原子能力项的能力定义和执行流程。所有实际计算逻辑、脚本调用、输出格式、质量检验标准均以各原子能力的 reference 为准。

## ⚠️ 全局强制约束

1. **脚本目录锚点**：本 Skill 的脚本目录为 `{SKILL_BASE_DIR}/scripts/`，其中 `{SKILL_BASE_DIR}` 取自系统注入的 "Base directory for this skill" 值
2. **必须调用真实脚本**：所有分析计算必须通过 Bash 工具执行 `scripts/` 下的 Python 脚本完成，不得以任何理由跳过
3. **禁止手写代码替代**：严禁绕过脚本，用手写 pandas / numpy / sklearn 等代码替代脚本功能。即使脚本报错，也应先排查修复，而非改用手写代码
4. **展示执行命令**：每次调用脚本时，必须在输出中展示完整的 bash 命令，让用户可审计实际执行内容
5. **路径解析规则**：所有 reference 中引用的 `../scripts/xxx.py` 路径，必须解析为 `{SKILL_BASE_DIR}/scripts/xxx.py` 绝对路径后执行

## 执行流程

### 步骤0：数据安全确认（必须优先进行）

在执行任何操作之前，必须向用户确认数据安全，并等待用户明确确认后才能继续：

```markdown
⚠️ 数据风险提示
若数据包含C4数据，请确认已开启安全屋模式后，继续分析。
** 请回复「确认」继续操作，或回复「取消」放弃本次分析。 **
```

执行规则：

- 每次正式调用分析能力前都必须执行本步骤，不能跳过
- 用户明确确认/选择后才能继续
- 用户取消、拒绝或未明确确认时，立即停止

如果用户确认：继续执行后续步骤。如果用户取消或未明确确认：终止本次操作，不得调用任何工具。

### 步骤 1：需求解析

分析用户输入，提取：

- 分析目标（描述/诊断/预测/解释/分群/检验）
- 数据特征（时序/截面/面板/事务型）
- 指标类型（连续/分类/生存时间）
- 是否需要多能力项组合

### 步骤 2：路由匹配

按规则 1 → 规则 1.5 → 规则 2 → 规则 3 的优先级，确定需要调用的原子能力项。若触发规则 3（回退），暂停流程等待用户确认后再继续。

### 步骤 3：加载原子能力项

读取匹配到的原子能力项的完整 reference 文件（路径见能力索引表），获取：

- 详细的工作流程步骤
- 脚本调用方式和参数
- 输出物格式要求
- 质量检验标准

### 步骤 3.5：脚本路径解析（强制）

所有原子能力项 reference 中引用的脚本路径 `../scripts/xxx.py`，必须解析为绝对路径后通过 Bash 工具执行：

```
脚本绝对路径 = {SKILL_BASE_DIR}/scripts/xxx.py
```

其中 `{SKILL_BASE_DIR}` 取自系统注入的 "Base directory for this skill" 值。

**强制要求**：
- 必须通过 Bash 工具执行 `python3 "{SKILL_BASE_DIR}/scripts/xxx.py" --input <数据文件>` 的形式调用脚本
- 禁止用手写 Python 代码替代 `scripts/` 下的脚本功能
- 每步必须展示实际执行的 bash 命令

### 步骤 4：按原子能力项定义执行

**严格按照原子能力项的reference中定义的工作流程执行**，包括：

- 按步骤顺序调用 `scripts/` 目录下的 Python 脚本
- 遵循其输入要求和参数配置
- 按其输出格式生成结果
- 按其质量检验标准进行自检
- 输出结果并提供总结

## 多能力项组合协议

当用户需求明确要求组合分析（如"先聚类再画像"、"先异常检测再归因"）时，按以下协议编排：

### 组合执行规则

1. **串行执行**：按分析逻辑顺序依次调用各原子能力项，前一个能力项完成后再执行下一个
2. **数据传递**：前一个能力项输出的 CSV 文件作为后一个能力项的输入文件，传递路径通过 `--output-dir` 和输入参数衔接
3. **中间产物保留**：每个能力项的输出文件均保留，不覆盖，以便用户追溯中间结果
4. **独立质检**：每个原子能力项独立执行其质量检验标准，任一能力项质检不通过则暂停并报告

### 常见组合模式

| 组合场景         | 调用链                                                                 | 数据传递方式                              |
| ---------------- | ---------------------------------------------------------------------- | ----------------------------------------- |
| 先检测异常再归因 | `anomaly-detection` → `drill-down`                                     | 异常标记结果 CSV → 下钻的输入数据         |
| 先聚类再画像     | `clustering` → `segment-aggregation`                                   | 含 cluster 列的 CSV → 按 cluster 分组汇总 |
| 先降维再聚类     | `dimensionality-reduction` → `clustering`                              | 降维后坐标 CSV → 聚类输入特征             |
| 先特征筛选再建模 | `driver-analysis` → `classification-forecast` 或 `regression-forecast` | 重要特征列表 → 建模特征选择               |
